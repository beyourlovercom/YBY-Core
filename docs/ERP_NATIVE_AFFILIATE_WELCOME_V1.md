# ERP native AffiliateWP welcome V1

Only new, explicitly opted-in ERP KOL accounts. Reuse AffiliateWP Application Accepted email and its subject/body settings, renderer and mail transport; no new plugin, template, UI, endpoint or table.

- Core: default off via `YBY_ERP_NATIVE_WELCOME_ENABLED` (boolean constant). Adds `{initial_password}` and `{coupon_code}` using AffiliateWP's native affwp_email_tags filter. Local AffiliateWP 2.27.4 archive confirms hook shape and affwp_notify_on_approval signature; verify installed version and hook contract at UAT.
- ERP1: default off via `KOL_CREATE_NATIVE_WELCOME=false`. New-account provision opts into deferral, then sends the initial password in the same live onboarding's HMAC-signed HTTPS Coupon request. Existing six-field Coupon identity, audit and idempotency storage exclude this transient secret. Non-opt-in calls unchanged.
- Suppress early approval only during authenticated opted-in creation. New exact account binding enrolls an option containing IDs/time only. Once exact live Coupon binding is ready, verify owner, active account, unique intended recipient, existing password hash, published/unexpired 20% Coupon, opt-in and configured body tags; native acceptance callback sends at most once. Atomic unique option claim, 15-minute eligibility, no automatic retry after transport ambiguity. Preview never exposes an initial password. An ambiguous preview coupon returns empty rather than picking arbitrarily. Native registration outside ERP retains its ordinary flow.
- Mail acceptance is not delivery. A failure leaves verified account and Coupon intact and requires manual review; do not recreate the user or retry a claimed credential-bearing email. No password stored by this adapter. Mail itself contains the initial password per Owner request; change it after login. Do not enable while request-body/exception-argument tracing, SMTP message-content logging, archive/BCC, or other credential-capturing tools are enabled. Verify actual runtime settings, TLS and recipient hooks before activation. No historical send or bulk backfill.
- Deployment order: verify both exact candidates, approved site release, both runtime flags initially OFF; pause new onboarding briefly during coordinated template/flag switch. Application Accepted body uses `{user_name}`, `{initial_password}`, `{coupon_code}`, `{referral_rate}`, `{referral_url}`, fixed 20% OFF. Never put passwords in subjects. Test one dedicated new account with explicit mailbox approval and validate genuine Gmail receipt. Do not use a real historical account or test credentials in GitHub.
- Evidence: PHP lint, native welcome isolated harness, all Connector harnesses and ERP feature tests. No actual Dev/WWW/ERP1 runtime writes or emails by this candidate. Release requires installed provider and actual mail logging/recipient verification.
